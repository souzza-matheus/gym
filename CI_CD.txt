================================================================================
GYMVISION — CI/CD (GitHub Actions)
================================================================================

Pipeline definida em: .github/workflows/ci.yml
Documentação em markdown (mesma informação): CI_CD.md / CI_CD_VISUAL.md

--------------------------------------------------------------------------------
1. QUANDO DISPARA
--------------------------------------------------------------------------------

  push        -> branches: main, master, develop
  pull_request -> branches: main, master

  Só push em main/master chega a publicar imagem e fazer deploy.
  Push em develop e PRs rodam só os jobs de teste/build.

--------------------------------------------------------------------------------
2. GRAFO DE DEPENDÊNCIA ENTRE JOBS
--------------------------------------------------------------------------------

  push/PR
     |
     |---------------------------------------------------------------+
     |                                                                |
     v                                                                v
  +----------------------+   +----------------------+   +------------------------+
  | user-service-test    |   | pose-service-test    |   | session-service-build  |
  | Gradle+Postgres+Redis|   | pytest               |   | Gradle (build -x test) |
  +----------------------+   +----------------------+   +------------------------+
     |                            |                            |
  +----------------------+   +----------------------+
  | dashboard-build      |   | android-build        |
  | npm ci + build       |   | Gradle assembleDebug  |

     |                            |                            |
     +--------------+-------------+--------------+--------------+
                     |

            +-----------------------+
            |   build-and-push      |   <- só roda se push em main/master

            +-----------------------+

  +----------------------+   +----------------------+

--------------------------------------------------------------------------------
4. PARA ONDE VÃO AS IMAGENS (build-and-push)
--------------------------------------------------------------------------------

  user-service          -+
  pose-service           |
  session-service        |        +-----------------------------------------+
  analytics-service      +------> | ghcr.io/<owner>/gymvision/<servico>     |
  backup-service         |        +-----------------------------------------+
  notification-service  -+
                          |
                          |        +-----------------------------------------+
                          +------> | docker.io/souzzamatheus/gymvision-<servico> |
                                   +-----------------------------------------+

  Cada serviço é publicado nos DOIS registries (mesma imagem, tags diferentes).

  dashboard (build estático) e android-app (gera .apk) NÃO geram imagem Docker.

--------------------------------------------------------------------------------
5. DEPLOY EM STAGING (sequência)
--------------------------------------------------------------------------------

  GitHub Actions                Docker Hub / ghcr.io          Servidor (staging)
  ---------------                ---------------------         -------------------
  build-and-push concluído
        |
        |-- conecta via SSH -------------------------------------->|
        |   (STAGING_HOST/USER/SSH_KEY)                            |
        |                                                          | docker compose pull
        |                                              <-----------| (baixa imagens :latest)
        |                                                          | docker compose up -d
        |                                                          |   --remove-orphans
        |<------------------------------ docker compose ps --------|
        |   (status final no log do Actions)

--------------------------------------------------------------------------------
6. SECRETS NECESSÁRIOS (GitHub -> Settings -> Secrets and variables -> Actions)
--------------------------------------------------------------------------------

  SECRET                 USADO POR              OBSERVAÇÃO
  ----------------------  ----------------------  --------------------------------
  GITHUB_TOKEN            login ghcr.io           Automático, não precisa criar
  DOCKERHUB_USERNAME   *  login Docker Hub        Username/organização do Docker Hub
  DOCKERHUB_TOKEN      *  login Docker Hub        Access Token (não usar a senha!)
                                                   Criar em: Docker Hub -> Account
                                                   Settings -> Security -> New
                                                   Access Token
  STAGING_HOST            deploy-staging          IP/hostname do servidor
  STAGING_USER            deploy-staging          Usuário SSH
  STAGING_SSH_KEY         deploy-staging          Chave privada SSH

  (*) PENDENTE — sem esses dois, o job build-and-push falha no login do
      Docker Hub e nenhuma imagem é publicada (nem no ghcr.io, pois o job
      inteiro falha nesse step).

--------------------------------------------------------------------------------
7. RODAR LOCALMENTE SEM ESPERAR O CI
--------------------------------------------------------------------------------

  # Testes (espelham os jobs *-test)
  cd user-service && ./gradlew test
  cd pose-service && pytest tests/

  # Build de imagem (espelha o build-and-push, sem publicar)
  docker build -t gymvision-pose-service ./pose-service

  # Validar o compose (espelha compose-validate)
  docker compose config --quiet
