1. VISÃO GERAL DO PROJETO
================================================================================

O GymVision é um sistema completo de monitoramento e correção de postura em
tempo real para academias. O sistema utiliza visão computacional e inteligência
artificial para analisar os movimentos do aluno durante exercícios físicos,
detectar erros biomecânicos e notificar o professor imediatamente.

O objetivo é reduzir o risco de lesões causadas por má execução de exercícios,
oferecendo feedback instantâneo tanto para o aluno (via app Android) quanto
para o professor (via dashboard web).

3. SERVIÇOS — DESCRIÇÃO TÉCNICA
================================================================================

3.1 POSE-SERVICE (Python / FastAPI — porta 8083)
────────────────────────────────────────────────
Responsabilidade: detecção de landmarks e análise biomecânica.

Tecnologias:
  - FastAPI (API assíncrona)
  - MediaPipe BlazePose (33 landmarks, fallback para MoveNet Thunder via TF Serving)
  - TensorFlow Serving (GPU-ready para produção)

Funcionalidades implementadas:
  a) Endpoint de análise por frame:
     POST /api/v1/pose/analyze
     - Recebe imagem JPEG + exercise_type + session_id + student_id + academy_id
     - Detecta 33 landmarks corporais
     - Calcula ângulos articulares (joelho, quadril, tornozelo, cotovelo, pulso)
     - Detecta a fase do movimento (STANDING / DESCENDING / BOTTOM / ASCENDING)
     - Executa análise específica do exercício
     - Publica alerta no RabbitMQ se risco MEDIUM ou HIGH
     - Retorna landmarks + análise em < 200ms

  b) Exercícios suportados com detecção de erros:
     ┌─────────────────┬──────────────────────────────────────────────────────┐
     │ Exercício       │ Erros detectados                                     │
     ├─────────────────┼──────────────────────────────────────────────────────┤
     │ Squat (Agacha.) │ Profundidade insuficiente, joelho para dentro        │
     │                 │ (valgus), coluna inclinada (frontal E lateral)       │
     ├─────────────────┼──────────────────────────────────────────────────────┤
     │ Deadlift        │ Lombar arredondada, quadril não estendido no topo    │
     ├─────────────────┼──────────────────────────────────────────────────────┤
     │ Lunge           │ Ângulo do joelho fora do ideal, tronco inclinado     │
     ├─────────────────┼──────────────────────────────────────────────────────┤
     │ Bench Press     │ Cotovelo muito aberto (risco de ombro), amplitude    │
     │                 │ insuficiente, pulso dobrado lateralmente              │
     ├─────────────────┼──────────────────────────────────────────────────────┤
     │ Bent-over Row   │ Lombar arredondada, remada incompleta                │
     └─────────────────┴──────────────────────────────────────────────────────┘

  c) Detecção de orientação de câmera:
     - Detecta automaticamente se a câmera está LATERAL, FRONTAL ou em ângulo
     - Regras perspectiva-dependentes são ativadas/desativadas conforme orientação
     - Knee cave: só detectado com câmera frontal (desvio medial visível)
     - Knee over toe: só detectado com câmera lateral (profundidade sagital)
     - Inclinação sagital do tronco: usa coordenada Z do MediaPipe em câmera frontal

  d) Sistema de score:
     - Base: 100 pontos por frame
     - Penalidade erro HIGH: -25 pts
     - Penalidade erro MEDIUM: -15 pts
     - Penalidade erro LOW: -5 pts
     - Fase UNKNOWN: score = 0

  e) Análise de vídeo completo:
     POST /api/v1/pose/analyze-video        → síncrono (vídeo curto)
     POST /api/v1/pose/analyze-video/async  → assíncrono (retorna job_id)
     GET  /api/v1/pose/analyze-video/status/{job_id} → polling de status

  f) Cache Redis:
     - Hash MD5 do arquivo de vídeo como chave
     - TTL 24 horas — vídeos idênticos não são reprocessados
     - Hit rate típico em laboratório: ~40% em treinos repetitivos

  g) Armazenamento MinIO:
     - Vídeos enviados são salvos em bucket "gymvision-videos"
     - Chave: {academy_id}/{session_id}/{timestamp}.mp4
     - URLs pré-assinadas (válidas 7 dias) para acesso posterior

  h) Fila assíncrona de vídeo:
     - asyncio.Queue com máximo 20 jobs simultâneos
     - Worker único (evita sobrecarga de GPU)
     - Status do job persistido no Redis (TTL 1h)

  i) Logs estruturados JSON:
     - Campos: timestamp, level, message, session_id, student_id
     - Compatível com Grafana/Loki para produção

3.2 SESSION-SERVICE (Kotlin / Spring Boot — porta 8084)
────────────────────────────────────────────────────────
Responsabilidade: ciclo de vida das sessões de treino.

Tecnologias:
  - Spring Boot 3 + Spring Data JPA
  - PostgreSQL (TimescaleDB) com Flyway migrations
  - RabbitMQ consumer/publisher

Funcionalidades:
  - CRUD de sessões (criar, iniciar, encerrar)
  - Registro de reps e alertas por sessão
  - Publica gym.session.ended ao encerrar
  - Migrations: V2 (errors TEXT), V3 (score DOUBLE PRECISION)

3.3 NOTIFICATION-SERVICE (Node.js / NestJS — porta 8085)
──────────────────────────────────────────────────────────
Responsabilidade: notificações em tempo real.

Tecnologias:
  - NestJS + Socket.IO (WebSocket)
  - Nodemailer (e-mail pós-sessão)
  - Web Push API (notificações no navegador)

Funcionalidades:
  - Consumer RabbitMQ → forward para professores via WebSocket
  - Rooms: academy:{id} — professor entra na sala da sua academia
  - Alertas em tempo real: < 500ms do frame ao professor
  - E-mail HTML automático ao encerrar sessão (score, reps, erros, comparativo)
  - Web Push: notificação no browser mesmo com aba fechada (VAPID keys)

3.4 USER-SERVICE (Node.js — porta 8081)
────────────────────────────────────────
  - Cadastro e autenticação de usuários (STUDENT / PROFESSOR / ADMIN)
  - JWT com refresh token automático
  - Endpoints: /register, /login, /refresh, /me, /users

3.5 ANALYTICS-SERVICE (Python / FastAPI — porta 8086)
───────────────────────────────────────────────────────
Responsabilidade: histórico, progresso e gamificação.

  - Consumer gym.session.ended → persiste resumos no MongoDB
  - Progresso semanal por aluno (score médio, erros dominantes)
  - Estatísticas da academia (alunos ativos, top erros, por exercício)
  - Leaderboard: ranking de alunos por score médio
  - Gamificação: pontos, nível, streak e 12 conquistas desbloqueáveis

  Sistema de pontos:
    - Cada sessão contribui com avg_score pontos ao total
    - Nível = pontos ÷ 500
    - Streak = dias consecutivos com ao menos 1 sessão

  Conquistas (exemplos):
    🏃 Primeira Sessão   ✅ Técnica Perfeita   🔥 10 Sessões
    💪 50 Sessões        📅 3 Dias Seguidos    🗓️ Semana Completa
    💯 100 Reps          🚀 1.000 Reps         ⭐ Score Perfeito
    🥈 Nível 5           🥇 Nível 10           🏆 Mestre da Forma

3.6 API GATEWAY (Kong — porta 8090)
─────────────────────────────────────
  - Roteamento de todas as requisições
  - Rate limiting:
      /api/v1/pose/analyze: 300 req/min
      /api/v1/pose/analyze-video: 10 req/min, 50/hora (proteção contra abuso)

8. FLUXO COMPLETO — CASO DE USO
================================================================================

1. Professor abre o dashboard (http://localhost:5173), faz login
2. Aluno abre o app Android, faz login e cria uma sessão (ex: Squat)
3. App exibe guia de câmera: dicas + animação de posicionamento
4. Aluno posiciona o celular e toca "Iniciar sessão"
5. CameraX captura frames a 30fps; app analisa 1 frame a cada 200ms
   ├── COM INTERNET: frame enviado via HTTP ao pose-service
   │     → MediaPipe detecta landmarks
   │     → exercise_analyzer calcula ângulos e detecta erros
   │     → se erro HIGH/MEDIUM: publica alerta no RabbitMQ
   │     → notification-service envia via WebSocket ao professor
   │     → app recebe landmarks e exibe overlay do esqueleto
   │     → app recebe alerta e: exibe banner + fala em voz PT-BR
   └── SEM INTERNET: ML Kit BlazePose detecta landmarks no dispositivo
         → mesma análise roda em Kotlin localmente
         → frame salvo no SQLite local
         → ao voltar online: WorkManager sincroniza em background
6. Professor vê alerta no dashboard em < 500ms
   - Badge de risco colorido (VERMELHO = HIGH, AMARELO = MEDIUM)
   - Mapa de calor atualizado em tempo real
   - Notificação no browser mesmo com aba fechada (Web Push)
7. Aluno finaliza sessão → session-service encerra e publica evento
8. analytics-service persiste resumo no MongoDB
9. notification-service envia e-mail HTML ao professor (score, reps, erros)
10. Aluno vê seu progresso na aba "Progresso" do app
11. Professor vê ranking atualizado no dashboard → aba "Ranking"

10. DIFERENCIAIS TÉCNICOS
================================================================================

  ► Análise multi-ângulo: o sistema detecta automaticamente a orientação da
    câmera (frontal, lateral, angled) e adapta as regras biomecânicas.
    Erros que só são visíveis em câmera frontal (knee cave) são ignorados
    quando a câmera está de lado — evitando falsos positivos.

  ► Resiliência offline total: o app Android continua funcionando sem internet,
    com análise de qualidade similar ao modo online (mesmo modelo BlazePose),
    e sincroniza automaticamente quando a conexão volta.

  ► Fan-out garantido: cada serviço consome sua própria fila no RabbitMQ.
    Se o notification-service estiver reiniciando, as mensagens ficam na fila
    e são entregues quando o serviço voltar — sem perda de alertas.

  ► Cache inteligente: análises de vídeo são cacheadas por hash MD5.
    O mesmo vídeo (mesmo arquivo) analisado uma segunda vez retorna em < 10ms
    independente da duração — sem reprocessamento.

  ► Processamento assíncrono de vídeo: vídeos longos não bloqueiam o servidor.
    O cliente recebe um job_id imediatamente e faz polling até o resultado ficar
    pronto — o servidor processa em background com fila asyncio.

  ► Arquitetura extensível: adicionar um novo exercício requer apenas:
    - 1 função _analyze_X() em exercise_analyzer.py (Python)
    - 1 valor no enum ExerciseType (Python e Kotlin)
    - Mapeamento de labels/ícones em RiskMappers.kt (Android)
    Todo o restante (routing, score, alertas, dashboard) funciona automaticamente.
